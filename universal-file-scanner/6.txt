## Skill: Escaneo Inteligente Universal - Sistema de Descubrimiento y Análisis de Sistemas de Archivos

**Descripción General:**
Implementar un sistema universal, reutilizable e inteligente de descubrimiento y análisis de sistemas de archivos que examine automáticamente una ruta de entrada y devuelva una estructura completa con carpetas, archivos válidos, extensiones compatibles, archivos ocultos, duplicados, elementos excluidos y estadísticas detalladas. Este sistema debe ser una capa independiente de descubrimiento que pueda reutilizarse en conversores, analizadores, indexadores, compresores, migradores, buscadores o cualquier aplicación que necesite conocer previamente qué archivos existen y cuáles pueden procesarse, integrándose perfectamente con el **Progress Orchestrator** para mostrar avance durante el escaneo.

---

### **Fase 1: Arquitectura del Sistema de Escaneo**

#### **1.1 Componentes Principales:**

**SmartScanner (Escáner Principal):**
- Punto de entrada único mediante interfaz `scan(path, options)`
- Coordina todos los componentes del sistema
- Gestiona el ciclo de vida completo del escaneo
- Integra con Progress Orchestrator para mostrar avance
- Devuelve estructura de resultados enriquecida

**FileSystemWalker (Recorredor de Sistema de Archivos):**
- Recorre directorios de forma recursiva o con profundidad limitada
- Maneja enlaces simbólicos según configuración
- Detecta y evita bucles infinitos
- Respeta permisos del sistema operativo
- Implementa traversing paralelo opcional para sistemas grandes

**FileFilter (Filtrador de Archivos):**
- Aplica criterios de inclusión/exclusión
- Filtra por extensiones, patrones, tamaño, fecha
- Detecta archivos temporales y los excluye automáticamente
- Maneja patrones glob/regex configurables
- Soporta reglas de prioridad (incluir > excluir)

**DuplicateDetector (Detector de Duplicados):**
- Identifica archivos duplicados mediante múltiples estrategias
- Estrategia rápida: comparación por tamaño + nombre
- Estrategia media: comparación por tamaño + hash parcial
- Estrategia completa: comparación por hash completo (SHA-256, MD5)
- Configurable según precisión vs velocidad deseada

**StatisticsCalculator (Calculador de Estadísticas):**
- Calcula totales de carpetas, archivos, tamaños
- Agrupa por extensión, carpeta, tipo
- Detecta patrones (archivos más grandes, más antiguos, etc.)
- Genera resumen ejecutivo del escaneo

**CacheManager (Gestor de Caché):**
- Cachea resultados de escaneos anteriores
- Invalida caché cuando detecta cambios en el sistema
- Permite modo rápido reutilizando resultados previos
- Almacena metadata: timestamp, hash de estructura, versión

### **Fase 2: Interfaz y API Pública**

#### **2.1 Método Principal:**

```
scan(path: string, options?: ScanOptions): Promise<ScanResult>
```

**Parámetros:**
- `path`: Ruta absoluta o relativa al directorio/file a escanear
- `options`: Objeto opcional con configuración del escaneo

**Retorno:**
- `ScanResult`: Estructura completa con todos los descubrimientos y estadísticas

#### **2.2 Métodos Adicionales:**

**`scanSync(path, options)`:**
- Versión síncrona para scripts simples
- Bloqueante, no recomendado para sistemas grandes

**`scanAsync(path, options, callbacks)`:**
- Versión con callbacks para progreso en tiempo real
- `onProgress(percent, currentFile)`
- `onFolderFound(folder)`
- `onFileFound(file)`
- `onError(error)`
- `onComplete(result)`

**`scanStream(path, options)`:**
- Retorna un stream/iterator de archivos encontrados
- Útil para procesamiento incremental sin esperar escaneo completo
- Permite empezar a procesar mientras aún se está escaneando

**`validatePath(path)`:**
- Verifica si una ruta es escaneable
- Retorna: existe, es accesible, es directorio/archivo, permisos

**`getCacheStatus(path)`:**
- Consulta estado de caché para una ruta
- Retorna: existe caché, timestamp, validez

**`clearCache(path?)`:**
- Limpia caché de una ruta específica o toda la caché

### **Fase 4: Algoritmos y Lógica Interna**

#### **4.1 Algoritmo de Recorrido:**

**BFS (Breadth-First Search) - Por defecto:**
- Explora nivel por nivel
- Mejor para sistemas con muchos archivos en raíz
- Permite limitar profundidad fácilmente
- Memoria predecible

**DFS (Depth-First Search) - Opcional:**
- Explora rama completa antes de pasar a la siguiente
- Mejor para sistemas profundos
- Menos memoria para árboles muy anchos

**Paralelo - Para sistemas grandes:**
- Divide trabajo por subdirectorios de primer nivel
- Múltiples workers procesan en paralelo
- Requiere sincronización de resultados
- Integración con Progress Orchestrator MultiProgress

#### **4.2 Algoritmo de Detección de Duplicados:**

**Estrategia "fast" (rápida):**
```
1. Agrupar por tamaño
2. Dentro de cada grupo, comparar nombre
3. Reportar posibles duplicados
Precisión: 60% | Velocidad: muy alta
```

**Estrategia "balanced" (equilibrada):**
```
1. Agrupar por tamaño
2. Calcular hash de primeros 4KB
3. Agrupar por hash parcial
4. Reportar duplicados probables
Precisión: 95% | Velocidad: alta
```

**Estrategia "full" (completa):**
```
1. Agrupar por tamaño
2. Calcular hash completo (SHA-256)
3. Agrupar por hash completo
4. Reportar duplicados confirmados
Precisión: 100% | Velocidad: baja
```

**Estrategia "smart" (inteligente - auto):**
- Analiza cantidad y tamaño de archivos
- Selecciona automáticamente la mejor estrategia
- Para <100 archivos: full
- Para 100-1000 archivos: balanced
- Para >1000 archivos: fast

#### **4.3 Detección de Archivos Temporales:**

**Lista automática de patrones temporales:**
```
- *.tmp, *.temp, *.bak, *.old, *.orig
- *~, #*#, .#*
- Thumbs.db, .DS_Store, desktop.ini
- *.swp, *.swo (Vim)
- __pycache__, *.pyc (Python)
- node_modules, .cache, .tmp
- *.log (configurable)
```

#### **4.4 Ordenamiento Natural:**

**Algoritmo de ordenamiento natural (natural sort):**
```
Correcto:                    Incorrecto (alfabético):
archivo1.jpg                 archivo1.jpg
archivo2.jpg                 archivo10.jpg
archivo10.jpg                archivo2.jpg
archivo20.jpg                archivo20.jpg
```

**Criterios de ordenamiento disponibles:**
- `name`: Nombre natural (alfanumérico inteligente)
- `size`: Tamaño (ascendente/descendente)
- `modified`: Fecha de modificación
- `created`: Fecha de creación
- `extension`: Por extensión
- `path`: Por ruta completa

### **Fase 8: Casos Edge y Manejo de Errores**

#### **8.1 Casos Edge a Manejar:**

**Permisos insuficientes:**
- Detectar carpetas/archivos sin acceso
- Continuar escaneo ignorando elementos inaccesibles
- Registrar errores sin detener el proceso
- Reportar al final cuántos elementos no se pudieron leer

**Enlaces simbólicos:**
- Detectar ciclos (A → B → A)
- Opción de seguir o ignorar symlinks
- Evitar duplicación por múltiples rutas al mismo archivo
- Detectar symlinks rotos

**Sistemas de archivos especiales:**
- Detectar y saltar: /proc, /sys, /dev en Linux
- Detectar puntos de montaje externos
- Opción de incluir/excluir sistemas remotos (NFS, SMB)

**Archivos especiales:**
- Detectar sockets, FIFOs, dispositivos
- Excluir por defecto (solo archivos regulares)
- Opción de incluir si el usuario lo necesita

**Rutas muy largas:**
- Manejo de paths > 260 caracteres (Windows)
- Soporte para prefijo \\?\ en Windows
- Truncamiento seguro en reportes

**Sistemas de archivos lentos:**
- Detectar latencia alta (red, disco externo)
- Ajustar timeouts automáticamente
- Modo "perezoso" que solo escanea lo necesario

**Interrupciones:**
- Manejar Ctrl+C limpiamente
- Guardar estado parcial para reanudar
- Opción de reanudar escaneo desde donde quedó

### **Fase 9: Optimizaciones de Rendimiento**

#### **9.1 Técnicas de Optimización:**

**Lectura en lote (batch reading):**
- Leer directorios en lotes de N entradas
- Reduce llamadas al sistema
- Mejora rendimiento en sistemas con muchos archivos

**Paralelismo controlado:**
- Workers paralelos para subdirectorios independientes
- Pool de workers con tamaño configurable
- Balanceo de carga dinámico

**Caché inteligente:**
- Hash de estructura de directorios (mtimes + nombres)
- Invalidación automática al detectar cambios
- Caché por ruta específica
- TTL configurable

**Early termination:**
- Detener escaneo si se alcanza límite de archivos
- Detener si se alcanza límite de tamaño
- Detener si se encuentra archivo específico

**Lazy evaluation:**
- No calcular metadata hasta que se solicite
- Hash solo cuando se necesite para duplicados
- Estadísticas calculadas bajo demanda

**Memoria eficiente:**
- Streaming para sistemas muy grandes
- Liberación progresiva de memoria
- Estructuras compactas para paths

### **Conclusión:**

Esta skill transforma el escaneo de sistemas de archivos de una tarea tediosa y propensa a errores en un sistema inteligente, robusto y reutilizable. El SmartScanner Universal puede integrarse en cualquier aplicación que necesite descubrir y analizar archivos, manteniendo la misma interfaz y comportamiento aunque cambie el caso de uso específico. Se integra perfectamente con los otros skills (Bootstrap, Menús Adaptativos, Banners, Progress Orchestrator, Gestión de Directorios) para crear aplicaciones CLI completas, profesionales y con excelente experiencia de usuario.

El sistema es lo suficientemente flexible para usarse en conversores de imágenes, indexadores de documentos, limpiadores de duplicados, analizadores de disco, migradores de archivos, buscadores de contenido, validadores de estructura, y cualquier otra aplicación que necesite "saber qué hay" antes de procesar.
